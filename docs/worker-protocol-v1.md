# Crystal Worker Protocol v1

## Scope

The local Crystal worker protocol is newline-delimited JSON over stdio. Version `1.0` is the contract between the public `@report-intelligence/crystal-client` package and the proprietary Windows Crystal worker.

- Standard output is reserved exclusively for protocol envelopes.
- Diagnostics and logs must be written to standard error.
- Each envelope occupies exactly one line.
- The public client rejects malformed JSON, oversized frames, unknown envelope shapes, and incompatible protocol versions.
- Request identifiers are opaque strings generated by the client.

## Ready envelope

The worker emits one ready envelope after startup:

```json
{"type":"ready","protocolVersion":"1.0","worker":{"name":"crystal-worker","version":"0.1.0"},"capabilities":["read_report","health_check","shutdown"]}
```

The client must not send requests until the ready envelope has been validated.

## Request envelope

```json
{"type":"request","protocolVersion":"1.0","id":"123","command":"read_report","args":["C:\\Reports\\sample.rpt",{}],"timeoutMs":60000}
```

The initial commands are:

- `read_report`
- `health_check`
- `shutdown`

## Success envelope

```json
{"type":"response","protocolVersion":"1.0","id":"123","ok":true,"result":{},"warnings":[]}
```

Warnings have a stable `code` and `message`, plus an optional `path` identifying the affected report element.
Standalone warning envelopes that include a request `id` and warnings in the final success envelope are correlated with that request. The public client exposes warning-aware `*Result` methods returning `{ data, warnings }`; data-only methods remain available for compatibility. MCP tools return extracted data as the first text content item and, when warnings exist, a second JSON text item shaped as `{ "warnings": [...] }` so incomplete or unsupported extraction is never silent.

Formula dependencies use stable prefixes: `field:`, `formula:`, `parameter:`, `runningTotal:`, and `sqlExpression:`. Subreport link fields include `mainReportField`, `subreportField`, and, when supplied by Crystal, `linkedParameterName`.

The Crystal worker emits these capability-specific warnings when the installed SDK cannot expose a structure:

- `UNSUPPORTED_DATABASE_JOINS`
- `UNSUPPORTED_SUBREPORT_LINKS`
- `UNSUPPORTED_CUSTOM_FUNCTIONS`

## Error envelope

```json
{"type":"response","protocolVersion":"1.0","id":"123","ok":false,"error":{"code":"FILE_NOT_FOUND","message":"Report file was not found.","retryable":false}}
```

Allowed error codes are defined by `WorkerErrorCodeSchema` in `packages/crystal-client/src/protocol.ts`. Worker responses must not include internal stack traces, credentials, passwords, complete connection strings, or sensitive environment values.

## Shutdown

The client requests graceful shutdown with the normal request envelope and command `shutdown`. The worker returns `{ "shuttingDown": true }`, releases open report handles, and exits. If the bounded shutdown period expires, the client terminates the child process.

## Compatibility

Version `1.0` requires an exact version match. A future compatible-version policy must be explicit; clients must not silently accept an unknown worker protocol.
