### Deep Feature-by-Feature Comparison

#### 1. Sections, Headers, and Footers
*   **SSRS / RDLC**: Employs a single body canvas nested between a page header and page footer. Report layout definitions map visual items with coordinate structures based on an absolute page size. Repeating column and row headers are defined inside Tablix data regions.
*   **JasperReports**: Features a vertical, band-oriented rendering layout. Developers place design elements inside dedicated bands (**Title, Page Header, Column Header, Group Header, Detail, Group Footer, Column Footer, Page Footer, Last Page Footer, Summary, and Background**). Multi-band capabilities apply to detail, group header, and group footer sections, allowing designers to break complex section contents into stacked logical rows. The **No Data** section is a specialized band that evaluates only if the primary datasource is empty, displaying a placeholder image or a custom empty-notice layout.
*   **FastReport**: Operates on a standard banded design where objects render top-to-bottom. Multi-level inheritance allows reports to inherit layouts from a base template. However, **base reports designed for twice-inherited templates have strict constraints**: they cannot contain complex objects (such as Tables or Matrices), scripts, parameters, or custom code blocks to avoid template compilation failures.
*   **DevExpress Reports**: Features a banded canvas structure where bands render sequentially from top to bottom on each page. Controls inside print relative to their parent band's structural role (e.g., detail bands print once per row; report headers print once per report). Master-detail layouts are managed seamlessly in a single file using **Detail Report Bands**, which print nested records by referencing defined relations inside the parent datasource.
*   **Stimulsoft Reports**: Contains a massive array of specialized page-level and report-level bands (**Report Title, Report Summary, Page Header/Footer, Group Header/Footer, Header/Footer, Column Header/Footer, Data, Hierarchical, Child, Empty, and Overlay**). In complex designs, headers and footers correspond strictly to their child data bands. **A Group Footer band will not output without its corresponding Group Header band**. To hide a band in the rendered report without breaking structural layout associations, developers must set its height to zero.

#### 2. Data Grouping
*   **SSRS / RDLC**: Managed through row and column group hierarchies within a Tablix layout region. Dynamic expressions are applied to individual group rows to compute running totals or nested group metrics.
*   **JasperReports**: Aggregates datasets sequentially. When a group's defined expression value changes, a group rupture occurs, triggering the execution of the group's header and footer sections. Multiple nested groups contain each other in the order they are declared. Importantly, **JasperReports does not sort incoming data during grouping**; records must already be ordered by the underlying datasource query for groupings to render correctly.
*   **FastReport**: Group bands execute grouping logic sequentially. As each new group prints, the engine automatically resets the value of the system-defined **`Row#`** variable, enabling accurate line-number counts within individual groups.
*   **DevExpress Reports**: Manages groupings via Group Header/Footer bands driven by programmatic expressions or query filters. Visual grouping rules can be applied dynamically in the designer using calculated fields.
*   **Stimulsoft Reports**: Supports robust visual data grouping using dedicated GroupHeader and GroupFooter bands. Group headers and footers should always be used in pairs to prevent unexpected rendering offsets. Inside interactive viewers, group headers support **dynamic collapsing**, allowing end users to collapse or expand nested rows by clicking on interactive **`[-]`** and **`[+]`** indicators.

#### 3. Parameters, Variables, and Expressions
*   **SSRS / RDLC**: Parameters are mapped to the built-in `Parameters` collection at runtime and can be used to filter dataset queries locally or on an SSRS server. RDL expressions can reference fields, globals, variables, and parameters.
*   **JasperReports**: Employs **Report Expressions** written in Java (default), Groovy, JavaScript, or BeanShell to calculate values on the fly. Report variables store calculated aggregates (sums, counts, averages) computed during template filling. Dynamic filters can be written directly inside database query strings using parameter syntax.
*   **FastReport**: References parameters inside expressions using square brackets `[ParameterName]`. Parameters support datatypes, names, and values, and can be updated programmatically from the parent host application using `report1.SetParameterValue("ParamName", value)`. Variables can be configured programmatically as system or script variables.
*   **DevExpress Reports**: Binds visual controls to data, calculates complex summaries, and applies conditional formatting using its native expression engine. Expressions can access row/column indexes, parent relations, and event-related variables.
*   **Stimulsoft Reports**: Expressions are defined within curly braces `{}`. Expressions support calling standard .NET Framework methods (e.g., `Trim()`, `ToUpper()`, `Math.Round()`, `Math.Sqrt()`). However, **nested code expressions are strictly forbidden when evaluating calculations**. Dictionary variables can be dragged directly onto the parameters panel, automatically rendering parameter drop-downs or calendar date pickers in the web viewer.

#### 4. Charts, Tables, and Cross Tabs
*   **SSRS / RDLC**: Integrates static chart types (e.g., bar, column, line, pie) and Tablix regions with row/column groupings. High-end interactive visual charts are not natively supported in standard local RDLC viewers.
*   **JasperReports**: Incorporates built-in charts using an extensible chart component that configures a chart dataset and plot settings. It supports Pie, Pie 3D, Bar, Bar 3D, Line, Area, Scatter Plot, Bubble, Gantt, and financial chart types. Standard **Crosstabs** aggregate multi-dimensional data into dynamic grids using row groups, column groups, and measures.
*   **FastReport**: Integrates the Microsoft Chart engine to display 30+ 2D/3D series types (e.g., columns, areas, lines, circular, pyramidal) with full control over style and visual behavior. The **Advanced Matrix Object** is a specialized pivot component supporting stepped forms, interactive collapsing collapse-buttons, and interactive row/column sorting. It can host Sparklines and Gauges inside individual grid data cells.
*   **DevExpress Reports**: Formats grid data using `XRTable` components. To handle rich HTML text formatting inside table cells, DevExpress recommends using its dedicated Word document model wrapper API (`XRRichText`). However, **using rich text components inside large tables introduces high memory overhead**, as a distinct Word document instance is initialized in memory for each cell.
*   **Stimulsoft Reports**: Natively supports complex charts (e.g., Sunburst, Box & Whisker, Waterfall, Pictorial Stacked, gauges, progress circles, online maps) and Cross-Tab components. Table cells support word-wrapping and truncation parameters to ensure precise alignment.

#### 5. Images, Subreports, and Drill-down
*   **SSRS / RDLC**: Images can be embedded inside the report, referenced via an external URL, or loaded directly from binary database fields. Subreports are linked locally, resolving parameters dynamically using C# event handlers.
*   **JasperReports**: Embeds static image graphics, scales SVGs, and maps dynamic hyperlinks to design elements to enable basic interactive drill-down pathways inside the Java printing viewer.
*   **FastReport**: The standard picture object displays external or database-sourced images. Advanced Matrix objects support interactive drill-down collapsing, and embedded subreports allow parent-child data grouping.
*   **DevExpress Reports**: Integrates image controls, watermarks, and native print-preview interactions (e.g., dynamic sorting, drill-down, drill-through). Subreports are treated as independent report definitions embedded inside a master report band.
*   **Stimulsoft Reports**: Supports loading local images, online map layers, shapes, and bookmarks. Its interactive web viewer handles dynamic sorting, collapsing, and drill-down by triggering its backend `OnInteraction` event or client-side `onInteraction` JavaScript handler. Subreports can link dynamically to external report templates using the `Interaction.Drill-Down Report` properties.

#### 6. Export Formats and Printing
*   **SSRS / RDLC**: Standard export options include HTML, PDF, IMAGE (TIFF/EMF), Excel, Word, CSV, and XML. Modern cross-platform re-compilations (e.g., `ReportViewerCore`) enable native rendering on Windows, Linux, and macOS environments.
*   **JasperReports**: Compiles raw JRXML layouts into ready-to-print `JasperPrint` objects, which are then exported directly to PDF, HTML, RTF, XLS, or CSV formats.
*   **FastReport**: Supports exporting compiled layouts to lossless, compressed `.fpx` prepared reports, PDF, Word 2007 (RTF), Excel 2007, PowerPoint, OpenOffice Calc, Calc, CSV, TXT, DXF, LaTeX, and XAML. Built-in cloud connectors can save exported files directly to OneDrive, Google Drive, Dropbox, FTP, or SMTP.
*   **DevExpress Reports**: Supports exports to PDF, HTML, XLS, XLSX, RTF, CSV, Image, and MHT. It focuses heavily on document accessibility, outputting fully tagged PDFs that conform to **PDF/A-1a, PDF/A-2a, PDF/A-3a, and PDF/UA-1** standards. For high-volume generation, DevExpress uses the streamed export class `PdfStreamingExporter` alongside `CachedReportSource` to write document streams directly to disk, avoiding server memory exhaustion.
*   **Stimulsoft Reports**: Highly portable template schema formats (**`MRT (XML)`**, **`MRT (JSON)`**, and **`MDC (JSON)`**) compile identically across cross-platform frameworks. Its unified exporting engine supports rendering to PDF, XPS, PPTX, HTML5 (SVG vectors), Word, Excel, ODT, ODS, RTF, CSV, JSON, XML, DBF, DIF, and SYLK. It provides direct web-printing APIs (`printPdf()`, `printWithoutPreview()`, and `printWithPreview()`) to output files seamlessly from frontend browsers.

#### 7. Scripting and Extensibility
*   **SSRS / RDLC**: Employs VB.NET script modules embedded inside RDL definitions. **To isolate untrusted scripting expressions, RDLC runs scripts within a sandboxed AppDomain**. Sandboxed compilation can be bypassed in fully trusted environments by calling `ExecuteReportInCurrentAppDomain` to improve processing speeds. Caching can be cleared dynamically using `ReleaseSandboxAppDomain` to reclaim host resources.
*   **JasperReports**: Dynamically compiles expressions using the Java, Groovy, or JavaScript compilers. Relational and programmatic data schemas are bound to report layouts by implementing the custom `JRDataSource` Java interface.
*   **FastReport**: Supports full C# and VB.NET scripting. **Report scripts can reference external assemblies (.dll or .exe) dynamically** within the options menu to execute complex compiled calculations during template rendering.
*   **DevExpress Reports**: Supports scripting on WinForms, WPF, ASP.NET Core, MVC, and Blazor Server, but **scripting is strictly unsupported on client-side Blazor WebAssembly**. To protect multi-user server environments from malicious code execution, DevExpress recommends using secure XML serialization over legacy CodeDOM serialization. Custom function wrappers can be registered inside expression trees.
*   **Stimulsoft Reports**: Incorporates a visual **Blockly-based script editor** (`blocklyEditor`) to program event-driven calculations on the client side without manual coding. Its modular web runtime allows specific engine modules (such as `reportsExport`, `reportsChart`, or `reportsMaps`) to be loaded separately, significantly reducing the initial page load footprint for web applications.
